# 开发文档：校友留言墙模块（后端 · Spring Boot + MySQL）

> 对接前端：`portal/src/components/MessageWall.tsx`
> 现状：内置 12 条演示便签 + 用户新增留言存 localStorage（仅本机可见），刷新不丢但**换设备/清缓存即失**。
> 本文档定义把留言迁到服务端所需的最小后端模块，遵循项目 P0 规范（统一信封 / snake_case / 分页 / ISO-8601 UTC 时间）。

---

## 1. 模块定性

| 维度 | 结论 |
|---|---|
| 内容性质 | 用户生成内容（UGC），**必须走审核**，不能直接公开显示 |
| 谁能写 | 仅登录用户（复用现有 JWT 认证）；留言人身份从档案自动带出 |
| 谁能读 | 公开（免登录可浏览，与门户"游客可看"定位一致） |
| 管理端 | school_admin / 校级管理员审核（通过 / 驳回 / 删除） |

> 与旧方案差异：不再允许未登录游客匿名留言。理由：留言墙挂在门户首页，匿名开放必然招垃圾信息；而登录态姓名/届次/学院可直接取自校友档案，防伪且少填三项表单。

## 2. MySQL 表设计

一张表即可，**不需要**为"置顶/推荐"单独建表（需要时加 `is_pinned` 字段）。

```sql
CREATE TABLE wall_message (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id       BIGINT UNSIGNED NOT NULL COMMENT '留言人 users.id',
  content       VARCHAR(120)    NOT NULL COMMENT '留言正文（前端限 40 字，DB 留冗余）',
  status        VARCHAR(16)     NOT NULL DEFAULT 'pending'
                                COMMENT 'pending=待审核 approved=已通过 rejected=已驳回',
  review_note   VARCHAR(255)    NULL COMMENT '驳回原因（可选，展示给用户）',
  reviewed_by   BIGINT UNSIGNED NULL COMMENT '审核人 users.id',
  reviewed_at   DATETIME        NULL,
  is_pinned     TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '置顶（预留，0=普通）',
  ip_addr       VARCHAR(45)     NULL COMMENT '提交 IP（风控用，不返回给前端）',
  created_at    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_status_created (status, created_at),
  KEY idx_user (user_id),
  CONSTRAINT fk_wall_user FOREIGN KEY (user_id) REFERENCES users (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='校友留言墙';
```

**说明：**

- **姓名 / 届次 / 学院不落库**：前端便签上的"林子轩 · 2023届 · 游戏产业学院"全部通过 `user_id` 关联 `users`/档案表联查得出。好处：用户改昵称/档案后留言墙自动更新，且杜绝"张冠李戴"的假身份。
- 字数限制：前端已限 40 字，后端仍需校验 `content` 长度 ≤ 120（防绕过前端直调接口）。
- 若联查届次/学院需回表多次，可在审核通过时冗余快照列（`grad_year`/`college_name`），见 §6 取舍。

## 3. API 设计（6 个接口）

统一信封：`{ "code": 0, "message": "ok", "data": { ... } }`

### 3.1 公开接口（免登录）

#### GET `/api/v1/wall/messages`

留言墙展示列表（**仅 approved**），按 `is_pinned DESC, created_at DESC` 排序。

| Query 参数 | 类型 | 说明 |
|---|---|---|
| `page` | int | 默认 1 |
| `page_size` | int | 默认 50，上限 100（前端一次拉全量铺墙） |

响应 `data`：

```json
{
  "total": 132,
  "list": [
    {
      "id": 101,
      "user_id": 5,
      "name": "林子轩",
      "grad_year": "2023届",
      "college": "游戏产业学院",
      "content": "愿我们不负青春，奔赴更好的未来",
      "is_pinned": 0,
      "created_at": "2026-09-20T08:30:00Z"
    }
  ]
}
```

> 注意字段命名与前端 `Note` 接口对齐：前端用 `gradYear/college`（camelCase），后端 snake_case，由前端做一层 `toNote()` 映射（见 §5）。

#### GET `/api/v1/wall/messages/mine`

当前登录用户的留言（**含 pending / rejected**，让用户知道自己的留言在审核中或被驳回及原因）。

权限：登录。响应同上，多返回 `status`、`review_note`。

### 3.2 用户接口（登录）

#### POST `/api/v1/wall/messages`

```json
{ "content": "把祝福留在墙上，把想念带回城堡" }
```

- 姓名/届次/学院不传，服务端从 `user_id` 关联取。
- 服务端校验：登录 + `content` 非空去空白后 1~120 字 + **提交频率限制**（见 §4）。
- 新留言一律 `status=pending`，响应返回创建结果（含 status），前端提示"已提交，审核通过后展示"。

#### DELETE `/api/v1/wall/messages/{id}`

用户撤回自己的留言（仅本人 + 任意状态可删；软删或物理删均可，建议物理删）。

### 3.3 管理端接口（school_admin）

#### GET `/api/v1/admin/wall/messages?status=pending&page=1&page_size=20`

审核队列，支持 `status` 筛选（pending/approved/rejected）+ `keyword` 模糊搜正文/留言人。

#### PUT `/api/v1/admin/wall/messages/{id}/review`

```json
{ "action": "approve" }        // 或 { "action": "reject", "note": "内容不符合社区规范" }
```

写入 `status / review_note / reviewed_by / reviewed_at`。

## 4. 风控与安全要点（Spring Boot 实现侧）

| 项 | 方案 |
|---|---|
| 频率限制 | 同一 `user_id` 每 60 秒最多 1 条、每天最多 5 条（Redis INCR 或 Caffeine 本地计数即可） |
| 敏感词 | 提交时过敏感词库（DFA），命中直接置 `rejected` + 默认原因，省一轮人工 |
| XSS | `content` 纯文本存储，前端以文本节点渲染（当前实现已是 `{n.text}` 文本插值，无富文本），后端再做一次 HTML 转义兜底 |
| 越权 | DELETE / review 必须校验属主或角色；管理端接口全部挂 `school_admin` 守卫 |
| 隐私 | 公开列表**不返回** `ip_addr`、手机号等任何个人信息；`user_id` 仅用于前端跳转档案（可选，不做也不影响） |

## 6. 可选增强（不阻塞联调，按需排期）

| 项 | 说明 |
|---|---|
| 身份快照列 | 审核通过时把 `grad_year/college_name` 冗余进表，列表免联查（数据量大后建议加） |

## 7. 验收清单

- [ ] 未登录 GET `/wall/messages` 返回 200 且只含 approved；POST 返回 401
- [ ] 登录后 POST 成功，返回 `status=pending`；公开列表**不出现**该条
- [ ] 同一账号 60 秒内第二条 POST 返回 429（或规范约定的限流 code）
- [ ] POST 121 字内容被 422 拒绝；纯空白被 422 拒绝
- [ ] 管理员 approve 后公开列表可见；reject 后 `/mine` 可见原因
- [ ] 用户 A 尝试 DELETE 用户 B 的留言 → 403
- [ ] 未登录访问 `/admin/wall/messages` → 401；普通校友访问 → 403
- [ ] 公开接口任何字段不含 ip / 手机号 / 身份证
- [ ] 分页：`page=2&page_size=50` 边界正确，`total` 准确
