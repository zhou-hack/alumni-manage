# 开发文档：优秀校友 & 校友档案索引模块

> 后端技术栈：Spring Boot + MySQL
> 前端：portal 门户（React，localhost:5173），数据层已预留对接点
> 对齐规范：《[定稿]API规范P0.md》通用约定（Base URL `/api/v1`、统一信封 `{code,message,data}`、snake_case、分页 `{list,total,page,page_size}`、时间 ISO 8601 UTC）
> 文档版本：v1.0（2026-09-20）

---

## 一、模块定位与现状

### 1.1 两个模块分别是什么

| 模块 | 位置 | 内容 | 数据性质 |
|---|---|---|---|
| **优秀校友** | 首页「优秀校友」环形展厅（AlumniSection + CircularGallery） | 16 位校友的照片、寄语、成长时间线、代表荣誉，点击弹出个人档案弹窗 | **运营精选**：管理员人工挑选并维护的展示位 |
| **校友档案索引** | 首页「优秀校友」下方（AlumniIndex） | 公开校友名录检索：关键词搜索 + 届次 chips + 姓名/学院/学号组合筛选，行尾箭头打开档案弹窗 | **公开档案聚合**：从已审核通过的校友数据聚合检索 |

### 1.2 前端现状（接后端前）

数据全部来自 `portal/src/mock/outstandingAlumni.ts`（16 条演示数据），组件已按「接后端只需替换取值」设计。前端数据契约如下：

```ts
interface OutstandingAlumni {
  name: string;          // 姓名
  photo: string;         // 照片 URL（空则前端渲染姓氏占位图）
  message: string;       // 一句话寄语
  college: string;       // 学院名称（展示用）
  gradYear: string;      // 毕业届次，如 "2023届"
  current: string;       // 当前身份：职位 / 城市，如 "前端开发工程师 / 福州"
  studentId: string;     // 学号（档案索引检索键）
  timeline: { year: string; event: string }[];   // 成长时间线
  awards: { title: string; year: string; level: string }[]; // 代表荣誉
}
```

## 二、总体设计

```
┌────────────────────────┐        ┌──────────────────────────────┐
│  优秀 alumni 精选位      │        │  校友档案索引（聚合检索）        │
│  outstanding_alumni 表  │        │  不建新表，SQL 聚合三张现有表：   │
│  (管理员人工维护)         │        │  users × archives × honors    │
└──────────┬─────────────┘        └──────────────┬───────────────┘
           │                                     │
           ▼                                     ▼
   GET /alumni/outstanding              GET /alumni/directory
   GET /alumni/directory/{student_id} ←─ 两模块共用详情弹窗
```

**设计决策**：

1. **优秀校友建独立表** `outstanding_alumni`——它是运营内容（精选、排序、寄语、时间线都是人工编辑的展示数据），不该从业务表推导。
2. **档案索引不建新表**——本质是「已公开校友」的检索视图，聚合 `users`（学籍）+ `archives`（公开档案）+ `honors`（荣誉）三张现有表。
3. **复用隐私红线**（与 `/screen/feed` 一致）：索引只收录存在 **approved 且已上架（published + consent 有效）档案** 的校友；未授权资料绝不出现在公开接口。

## 三、MySQL 表设计

### 3.1 优秀校友表（新建）

```sql
CREATE TABLE outstanding_alumni (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id       BIGINT        NOT NULL COMMENT '关联 users.id（必须是已激活校友）',
  student_id    VARCHAR(20)   NOT NULL COMMENT '冗余学号，便于检索与关联档案索引',
  display_name  VARCHAR(50)   NOT NULL COMMENT '展示姓名',
  photo_url     VARCHAR(500)  NULL     COMMENT '照片URL；NULL时前端渲染姓氏占位图',
  message       VARCHAR(200)  NULL     COMMENT '一句话寄语',
  college_id    BIGINT        NULL     COMMENT '关联字典 college（dicts 表 college 项）',
  grad_year     SMALLINT      NULL     COMMENT '毕业年份，如 2023',
  current_title VARCHAR(100)  NULL     COMMENT '当前职位，如 前端开发工程师',
  current_city  VARCHAR(50)   NULL     COMMENT '当前城市，如 福州',
  timeline      JSON          NULL     COMMENT '成长时间线 [{\"year\":\"2020\",\"event\":\"...\"}]',
  awards        JSON          NULL     COMMENT '代表荣誉 [{\"title\":\"...\",\"year\":\"2022\",\"level\":\"省级\"}]',
  display_order INT           NOT NULL DEFAULT 0 COMMENT '展示顺序，小者靠前',
  is_featured   TINYINT(1)    NOT NULL DEFAULT 0 COMMENT '是否首页焦点推荐位',
  status        VARCHAR(20)   NOT NULL DEFAULT 'draft' COMMENT 'draft/published/withdrawn',
  created_at    DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_user_id (user_id),
  KEY idx_status_order (status, display_order),
  KEY idx_grad_year (grad_year),
  KEY idx_student_id (student_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  COMMENT='优秀校友展示位（运营精选，school_admin 维护）';
```

> 说明：`timeline` / `awards` 用 MySQL 5.7+ 的 JSON 类型；若 MySQL 5.6 及以下改用 `TEXT` 存 JSON 字符串。`status` 沿用公告模块的 draft→published↔withdrawn 语义。

### 3.2 档案索引：不建新表，聚合查询

前置条件（复用现有数据）：

| 数据 | 来源表 | 公开条件 |
|---|---|---|
| 校友姓名/学号/学院/届次 | `users`（+ `dicts` college） | 满足下方档案公开条件 |
| 公开档案数 | `archives` | `status='approved'` 且已上架（showcase published）且 consent 有效 |
| 荣誉（含级别） | `honors` | `status='approved'`（或业务上视为终态通过的荣誉） |
| 当前身份 | `outstanding_alumni.current_title/current_city`（如有）否则展示「XX届校友」 | — |

**建议加索引**（如尚无）：

```sql
ALTER TABLE archives ADD INDEX idx_status_published (status, published);
ALTER TABLE honors   ADD INDEX idx_owner_status (user_id, status);
ALTER TABLE users    ADD INDEX idx_grad_year (grad_year);
```

## 四、API 设计（对齐 API 规范 v1）

所有端点 Base URL 为 `/api/v1`，响应统一信封 `{code, message, data, request_id, timestamp}`，分页参数 `page / page_size`。

| `college_id` | 学院（精确，字典 id） |
| `student_id` | 学号（包含匹配） |

```json

  "student_id": "202102002",
  "name": "陈思远",
  "photo_url": null,
  "college": "智能产业学院",
  "grad_year": 2024,
  "current": "前端开发工程师 / 福州",
```

- `timeline` / `awards` / `message`：若该校友在 `outstanding_alumni` 有记录则返回编辑内容；否则 `timeline` 由其公开档案按年份聚合生成、`awards` 取 approved 荣誉、`message` 为 null。

### 4.2 管理端点（school_admin）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/outstanding-alumni` | 全量列表（含 draft/withdrawn），支持 `status` 筛选 |
| POST | `/admin/outstanding-alumni` | 新增精选校友。校验：`user_id` 必须是已激活校友；重复添加 `409 + INVALID_STATE` |
| PATCH | `/admin/outstanding-alumni/{id}` | 修改展示信息 / 排序 / 上下架（status） |
| DELETE | `/admin/outstanding-alumni/{id}` | 移除精选位（物理删除或软删均可，建议软删） |

字段校验：`display_name` ≤50、`message` ≤200、`timeline` 数组 ≤20 项、`awards` ≤20 项、`grad_year` 2000~当前年。

### 5.1 分层与代码结构

```

│   ├── AlumniPublicController    # /alumni/*（公开）

├── entity                        # OutstandingAlumniEntity

```

### 5.2 关键 SQL（档案索引聚合）

```sql
-- directory 列表：只收录有公开档案的校友
SELECT u.student_id,
       u.nickname                        AS name,
       c.label                           AS college,
       u.grad_year,
       oa.current_title,
       oa.current_city,
       oa.photo_url,
       (SELECT h.title FROM honors h
         WHERE h.user_id = u.id AND h.status = 'approved'
         ORDER BY FIELD(h.level,'national','provincial','city','school') ASC, h.awarded_at DESC
         LIMIT 1)                        AS top_honor,
       COUNT(DISTINCT a.id)              AS archive_count
FROM users u
LEFT JOIN dicts c          ON c.value = u.college_code AND c.type = 'college'
LEFT JOIN outstanding_alumni oa ON oa.user_id = u.id AND oa.status = 'published'
JOIN archives a            ON a.owner_user_id = u.id
                          AND a.status = 'approved'
                          AND a.published = 1
WHERE /* 动态条件：name/grad_year/college_id/student_id/keyword */
GROUP BY u.id
ORDER BY u.grad_year DESC, u.student_id ASC
LIMIT #{page_size} OFFSET #{offset};
```

> `keyword` 综合搜索建议：`u.nickname LIKE CONCAT('%',#{kw},'%') OR u.student_id LIKE ... OR EXISTS (SELECT 1 FROM honors h WHERE h.user_id=u.id AND h.title LIKE ...)`。数据量大时给 `honors.title` 加 FULLTEXT 索引或引入 ES，MVP 用 LIKE 即可。

### 5.3 缓存与性能

- 三个公开 GET 接口加 `@Cacheable(cacheNames="alumniPublic", key="#root.methodName + ':' + #queryString")`（Caffeine，**TTL 5 分钟**）；管理端写操作 `@CacheEvict` 全量失效。
- 目录列表 `COUNT` 与明细分两条 SQL，避免 `GROUP BY + COUNT` 双重扫描。
- 单页上限 100，`page_size` 超限返回 `400 + INVALID_PARAMETER`。

### 5.4 时间序列化（对齐规范 1.5）

```yaml
spring:
  jackson:
    date-format: yyyy-MM-dd'T'HH:mm:ss'Z'
    time-zone: UTC
```

`LocalDateTime` 字段统一输出 ISO 8601 UTC；纯日期字段（`awarded_at` 等）保持 `YYYY-MM-DD` 字符串。

### 5.5 全局异常 → 统一信封

复用现有 `@RestControllerAdvice`：`NOT_FOUND(404)`、`INVALID_PARAMETER(400)`、`INVALID_STATE(409)`、`FORBIDDEN(403)`，`message` 直接给用户可读文案。

## 六、隐私与安全红线（必须遵守）

1. **公开接口绝不返回**：手机号、身份证号、班级、辅导员的任何字段——`users` 表只有 nickname/student_id/college/grad_year 允许出参。
2. **档案只出 approved**：`archives.status='approved'` 且已上架（published + consent 有效）；驳回/草稿/删除审核中的一律不可见——与 `/screen/feed` 同一红线。
3. **荣誉只出 approved**：驳回中的荣誉不出现在索引与详情。
4. **照片 URL**：存独立 CDN/OSS 地址，不要复用附件表 `biz_type=avatar` 的带鉴权预览链接（公开接口无法带 Bearer）。
5. 管理端点必须校验 `school_admin` 角色；公开端点不做鉴权但要做 **接口限流**（如 IP 60 次/分钟，防爬）。
