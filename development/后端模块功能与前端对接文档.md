## 一、部署形态与连接方式

### 1. 后端地址（模块化单体）

```
Base URL:  http://127.0.0.1:8080/api/v1
```

全部 10 个模块运行在**同一端口 8080**（PlatformApplication 模块化单体），无端口冲突、无跨模块转发，前端只配一个地址。

### 2. 通用约定

| 项目 | 约定 |
|------|------|
| 认证 | `Authorization: Bearer <access_token>`（JWT，HS256，payload 含 sub/role/exp） |
| 响应格式 | 统一 `{ code, message, data, request_id, timestamp }`，业务数据在 `data` |
| 时间格式 | ISO 8601 |
| 跨域 | 后端 CORS 已放行（`allowedOriginPatterns("*")`），任何前端开发端口可直接调 |
| 错误码 | `INVALID_PARAMETER`(400) / `UNAUTHORIZED`(401) / `FORBIDDEN`(403) / `NOT_FOUND`(404) / `INVALID_STATE`(409) / `INTERNAL_ERROR`(500) |

### 3. 最小对接示例

```js
// 1) 登录（密码必须先在前端 SHA-256，传 64 位小写 hex）
const sha256Hex = async (t) => {
  const b = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(t));
  return [...new Uint8Array(b)].map(x => x.toString(16).padStart(2, '0')).join('');
};
const login = await fetch('http://127.0.0.1:8080/api/v1/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ phone: '13900010003', password: await sha256Hex('原始密码') }),
}).then(r => r.json());
const token = login.data.access_token;   // 后续请求携带

// 2) 调任意业务接口
const my = await fetch('http://127.0.0.1:8080/api/v1/archives/my', {
  headers: { Authorization: 'Bearer ' + token },
}).then(r => r.json());
```

## 二、模块功能一览

| 模块 | 前端能用来做什么 | 权限边界 |
|------|----------------|----------|
| Auth 认证 | 登录、发验证码、三要素激活核验、当前用户信息、刷新令牌 | 部分接口免认证 |
| Dicts 字典 | 学院/专业/荣誉分类下拉选项；管理员维护字典 | 读=登录即可，写=school_admin |
| Archives 档案 | 校友提交/查看档案（获奖、经历、证书…） | 学生管自己的，管理员看列表 |
| Honors 荣誉 | 荣誉申报、列表筛选、详情、修改 | 学生/alumni 申报，重复申报 409 |
| Reviews 审核 | 两级审核待办、通过/驳回 | 院级初审、校级复核 |
| Attachments 附件 | 文件上传、图片预览、管理员删除 | 上传=登录，删除=管理员 |
| Imports 导入 | CSV 模板下载、批量导入校友、进度轮询、错误报告 | college_admin |
| Consents 授权 | 档案公开展示授权、撤回（联动下架） | 本人档案 |
| Showcase 大屏 | 公开轮播墙（**免 Token**）、上架/下架 | 读=公开，上下架=school_admin |
| Stats 统计 | 平台总览、学院排行、荣誉分布 | 仅管理员 |

## 三、各模块接口明细

### 1. Auth 认证

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| POST | `/auth/login` | 免认证 | 密码登录。body: `{phone, password}`，password 为 SHA-256 后的 64 位 hex。返回 `access_token / refresh_token / user` |
| POST | `/auth/sms` | 免认证 | 发送短信验证码。body: `{phone, scene}`（缺 scene 返回 400） |
| POST | `/auth/activate/verify` | 免认证 | 三要素核验（激活第一步）。body: `{student_id, real_name, id_card}`，与校友库比对失败返回 400 `AUTH_VERIFY_FAILED`。**限流：单 IP 10 次/小时、单学号 5 次/天** |
| GET | `/auth/me` | 登录 | 当前用户信息 |
| POST | `/auth/refresh` | 免认证 | 刷新令牌（轮换制）。body: `{refresh_token}` |

### 2. Dicts 字典

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| GET | `/dicts/{type}` | 登录 | 取字典项。type: `college`（3 个学院）/ `major`（专业，按学院分组）/ `honor_category`（荣誉分类）/ `grad_year`（**虚拟类型**，动态生成毕业年份区间，不查表）。未知 type 返回 404 |
| POST | `/dicts/{type}` | school_admin | 新增字典项。body: `{label, value, parent_id?, sort?}`。学生调用 403 |

### 3. Stats 统计（仅管理员）

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| GET | `/stats/overview` | college_admin / school_admin | 平台总览：校友数、待审数、荣誉总数等 |
| GET | `/stats/colleges?limit=N` | college_admin / school_admin | 学院排行（按 archives ⋈ users ⋈ alumni_base 聚合） |
| GET | `/stats/honors` | college_admin / school_admin | 荣誉分布（按 category × level 聚合） |

### 4. Reviews 审核

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| GET | `/reviews` | college_admin / school_admin | 审核待办。默认看自己级别；`?stage=second` 看复核 |
| POST | `/reviews/{id}/approve` | 对应级别管理员 | 通过审核（不存在 id 返回 404） |
| POST | `/reviews/{id}/reject` | 对应级别管理员 | 驳回。body: `{reason}`（必填，否则 400） |

### 5. Archives 档案

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| GET | `/archives/my` | student / alumni | 本人档案列表 |
| GET | `/archives` | 审核角色 | 管理端档案列表（学生访问 403） |
| POST | `/archives` | student / alumni | 创建档案。body: `{title, category, content?, submit?}`，title 必填 |
| GET | `/archives/{id}` | 按归属/角色 | 档案详情（不存在 404） |

### 6. Honors 荣誉

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| GET | `/honors` | 登录 | 荣誉列表（支持筛选/分页） |
| GET | `/honors/{id}` | 登录 | 荣誉详情 |
| POST | `/honors` | student / alumni | 申报荣誉。body: `{title, category, level, awarded_at, attachment_ids?}`。**防重复**：同人+同标题+同日期且未终态 → 409 `INVALID_STATE` |
| PATCH | `/honors/{id}` | 本人 | 修改荣誉（重新进入审核） |

### 7. Attachments 附件

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| POST | `/attachments` | 登录 | 上传文件。`multipart/form-data`: `file` + `biz_type`（archive/honor/avatar…），返回附件 id。未引用的孤儿附件 24h 后自动清理 |
| GET | `/attachments/{id}/preview` | 登录 | 预览/下载文件内容（二进制流） |
| DELETE | `/attachments/{id}` | 管理员 | 删除附件（强制留审计日志）。学生 403 |

### 8. Imports 批量导入

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| GET | `/imports/template` | college_admin | 下载导入模板（二进制文件） |
| POST | `/imports` | college_admin | 上传 CSV 导入校友。`multipart/form-data`: `file`（≤10MB），返回 `import_id`。异步处理，**坏行不阻断好行** |
| GET | `/imports/{id}` | college_admin | 查询任务进度：`{status: processing|done, total, success, failed}`（前端轮询至 done） |
| GET | `/imports/{id}/errors` | college_admin | 错误报告：`{list: [{row_no, student_id, reason}]}` |

### 9. Consents 隐私授权

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| GET | `/consents/my` | 登录 | 本人授权记录列表 |
| POST | `/consents` | student / alumni | 创建授权。body: `{archive_id, scope}`，scope: `screen`（大屏）/ `site`（预留）。同一档案同一 scope 重复授权 409；他人/不存在档案 404 |
| DELETE | `/consents/{id}` | 本人 | 撤回授权，**自动联动下架对应大屏展示** |

### 10. Showcase 大屏 / 上下架

| 方法 | 路径 | 权限 | 功能 |
|------|------|------|------|
| GET | `/screen/feed` | **免认证（公开）** | 大屏轮播墙数据：封面/标题/分类/校友/学院/毕业年份 |
| POST | `/showcase/{archive_id}/publish` | school_admin | 上架档案（前置：档案 approved 且有有效 consent） |
| POST | `/showcase/{archive_id}/unpublish` | school_admin | 下架 |

## 四、典型前端页面的接口编排

| 页面类型 | 编排流程 |
|----------|----------|
| 登录/激活页 | `/auth/activate/verify`（三要素）→ `/auth/sms`（发码）→ 设密码 → `/auth/login` → 存 token → `/auth/me` 渲染用户 |
| 校友档案工作台 | `/dicts/college` + `/dicts/grad_year`（下拉）→ `POST /archives` → `POST /attachments`（传材料，拿 id 填入 attachment_ids）→ `/archives/my` 列表 |
| 荣誉申报 | `/dicts/honor_category`（分类下拉）→ `POST /honors`（重复提交给 409 提示"已申报过"）→ `/honors?status=` 查进度 |
| 管理员审核台 | `/reviews`（待办）→ 详情 → approve / reject（reason 必填）→ `/stats/overview` 看板 |
| 批量导入向导 | `/imports/template` 下载模板 → 选文件 `POST /imports` → 每 600ms `GET /imports/{id}` 轮询 → done 后 `GET /imports/{id}/errors` 渲染坏行表格 |
| 公开大屏 | `GET /screen/feed`（免 Token）→ 前端 3s 轮换卡片；可选 10s 自动刷新 |
| 授权管理 | `/archives/my` 选档案 → `POST /consents`（scope=screen）→ `/consents/my` 列表 → 撤回触发大屏自动下架 |

## 五、注意事项与已知边界

1. **登录密码不是明文**：前端先 `SHA-256` 再传 64 位小写 hex，传明文/非 hex 会 400（最高频的对接错误）。
2. **第十二章 Drafts（服务端草稿）后端未实现**，前端草稿暂存 localStorage 兜底。
3. **`/screen/feed` 是唯一免认证接口**，适合大屏/公示场景；其余全部需要 Bearer Token。
4. **三要素核验有防爆破限流**（IP 10 次/时、学号 5 次/天），压测时注意，被限流返回 429。
5. **附件孤儿清理**：上传后 24h 内未与业务记录关联（ref_id）会被定时清理，前端拿到附件 id 后应尽快提交业务表单。
6. **字典数据现状**：college 3 项、honor_category 4 项、major 仅 2 项（通信工程/车辆工程）；导入的专业文本尚未与字典强制校验，新前端的专业下拉建议直接取 `/dicts/major` 保证口径一致。
7. **角色越权一律 403**：前端按 role 渲染菜单即可，后端有统一兜底拦截，无需重复防御。
8. **现成参考实现**：`Frontend/` 下 6 个测试页（index/reviews/showcase/consents/honors/apitest）覆盖了上述全部模块的调用写法，可直接抄；`apitest.js` 的 53 条用例是最小调用示例集。
