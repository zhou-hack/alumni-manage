## 2. 项目背景与建设目标

### 2.1 项目背景

学校学生与校友资料分散于学工、教务、二级学院、社团及个人，存在档案重复、信息更新不及时、素材难复用、优秀案例缺少展示的问题。

平台分阶段建设：**第一步（P0/MVP）** 先跑通「登录—上传—审核—展示」闭环；**后续（P1–P3）** 逐步扩展三级审核、增强检索、人脸（评估后）、AI、职工系统集成等能力，最终形成「数据资产 + 关系运营 + 合作转化」三位一体的校友管理平台。

### 2.2 建设目标

| 阶段 | 目标 | 衡量口径 |
|---|---|---|
| P0（MVP） | 四项核心闭环 | 登录、上传（批量）、展示、两级审核可用；本周基础版、下周上线 |
| P1 | 近期迭代 | 三级审核、智能标签与增强检索、消息通知、细粒度权限与审计、大屏自适应 |
| P2 | 中期增强 | 人脸（评估后）、热度榜单、留言互动、时间轴、AI、驾驶舱、小程序、视频 |
| P3 | 远期预留 | 双屏方案、职工系统集成、多校区、数据开放、校友圈、统一身份 |

## 4. 术语说明与用户角色

### 4.1 术语说明

| 术语 | 定义 |
|---|---|
| 校友管理平台 | 本项目最终产品名称（数据资产 + 关系运营 + 合作转化三位一体） |
| MVP | 最小可行产品，仅交付「登录—上传—审核—展示」闭环 |
| 学号 | 校友/学生唯一业务标识，字符串存储、保留前导零 |

| 荣誉（统一） | 荣誉、证书、奖项统一为「荣誉」实体，不再分模块；通过类别字典区分，证书原件可上传附件、无原件则文字记录 |
| 荣誉类别 | 奖学金、三好学生、优秀干部、证书、奖项、社会贡献等分类字典，用于分类与筛选 |
| 两级审核 | P0：院系初审 → 校级复核 |
| 三级审核 | P1：导员（辅导员）初审 → 院系复审 → 校级终审 |
| 导员（辅导员） | 院级以下的管理层级，负责所带学生资料的初审与管理（P1 引入） |
| 批量备注 | 一次对多张图片/多份材料统一填写说明，降低录入成本 |
| 三级组织权限 | 学生/校友—院系—学校（含领导层）三级数据权限 |
| 大屏 | 网页先行；双屏（宣传＋数据可视化）为 P3 |

| 角色 | 职责 | 数据范围 |

| 校领导（领导层） | 校级看板与数据可视化 | 校级聚合数据（只读） |
| 未登录参观者 | 浏览大屏公开内容 | 已审核、已上架内容 |
| 集成服务账号（P1+） | 数据交换与设备事件 | 指定接口和字段 |

## 5. 总体架构与端口说明

### 5.1 总体架构

| 层级 | 内容（P0） | 内容（P1+ 扩展） |
|---|---|---|
| 访问层 | PC 端（PC Web，面向所有角色、全量功能）、校友端 H5（主要面向校友）、大屏（网页） | 人脸终端、独立小程序、职工子系统（预留） |
| 业务层 | 认证、档案、荣誉（统一）、审核、展示 | 标签检索、消息、互动、AI |
| 公共能力层 | 认证、权限（三级基础）、附件、审核流、字典 | 标签、消息、审计、检索 |
| 数据层 | 校友档案、荣誉（含类别）、附件、审核日志 | 人脸特征（加密） |
| 集成层 | 学工/教务数据导入（Excel/CSV） | API/中间库/事件通知 |

**技术基线**：校内专网部署；Docker 容器；接口统一请求/响应/错误码格式并自查优化；P1 起引入 Redis 缓存支撑大屏热点与检索。

### 5.2 端口说明

| 端口 | 定位 | 层级 |
|---|---|---|
| PC 端（管理后台/网页，面向所有人） | 面向学生、校友、导员、各级管理员、领导层等所有角色，**全量功能可用**：注册登录、资料上传、荣誉管理、审核、上架、字典、统计、检索、展示等 | P0，PC Web |
| 校友端 H5（主要面向校友） | 主要面向校友（含在校学生）的移动端入口：注册登录、资料上传、查看审核状态 | P0 优先 H5；独立小程序 P2 |
| 大屏端（网页） | 公开展示 | P0 单屏网页；屏幕自适应 P1；双屏 P3 |
| 人脸终端 | 人脸识别联动 | P2（评估后） |
| 数据集成端 | 数据接入、同步、对账 | P0 基础（导入）/P1 增强（API/中间库） |
| 职工管理子系统（预留） | 职工与校友身份映射 | P3 |

## 6. 功能需求

### 6.1 通用规则

1. 需求采用「模块编号－功能编号」，关联开发任务与验收。
2. 荣誉、证书、奖项统一为「荣誉」实体，**不再分模块**；通过类别字典区分，证书原件上传附件、无原件文字记录。
3. 资料修改或驳回重提生成新版本并重新审核。
4. 服务端统一校验权限，知道学号不代表有权查询他人资料。
5. 联系方式默认脱敏展示；公开展示须本人授权且经审核。
6. `person_uuid` 作为跨系统技术标识（P3 预留），不替代学号、不对外公开。

## 8. 核心业务流程

### 8.1 账号注册与登录（P0）

学生：学号＋姓名＋身份证后6位 → 教务校验 → 注册 → 登录（初始密码强制改密）。
校友：手机/邮箱注册 → 毕业信息核验 → 认证激活 → 登录。忘记密码：身份证要素＋绑定手机找回。

### 8.2 资料上传与审核

- **P0（两级审核）**：选择类别 → 填表 → 批量上传附件＋批量备注 → 草稿/提交 → 上报院系初审 → 校级复核 → 入库 → 申请展示上架。
- **P1（三级审核）**：提交 → 导员初审 → 院系复审 → 校级终审 → 入库 → 申请展示上架。

| 环节 | 说明 |
|---|---|
| 批量上传 | 多图片/多材料一次选择，统一备注，降低录入成本 |
| 驳回 | 必填原因，重提生成新版本 |
| 展示 | 仅已审核＋本人授权＋已上架内容可在大屏展示 |

### 8.3 大屏展示（P0 单屏）

单屏网页轮播/列表展示荣誉、优秀校友、招生简章类内容；检索：学号＋学院/届别/荣誉类别等多级筛选。双屏（宣传＋数据可视化）为 P3。

### 8.4 后续流程（P1/P2 规划）

| 流程 | 层级 | 链路 |
|---|---|---|
| 三级审核 | P1 | 提交 → 导员初审 → 院系复审 → 校级终审 |
| 人脸到访 | P2 | 单独授权 → 识别 → 受控映射 → 欢迎轮播 → 超时恢复公共页 |

## 9. 数据与接口要求

### 9.1 数据标识

| 规则 | 说明 |
|---|---|
| 业务标识 | 学校正式学号（`alumni_id`，字符串，保留前导零），不生成替代业务ID |
| 技术标识（P3） | `person_uuid`，不可枚举、不对外公开，用于跨系统关联 |
| 荣誉类别 | 奖学金/三好/证书/奖项/社会贡献等类别字典，用于分类与筛选，不再分模块 |
| 证书原件 | 有原件上传附件，无原件文字记录 |

### 9.2 核心数据对象

| 对象 | 标识 | 说明 |
|---|---|---|
| 校友档案 | `alumni_id` | 关联账号与全部资料 |
| 荣誉（统一） | `honor_id` + 类别 | 荣誉/证书/奖项统一存储，类别区分 |
| 附件 | `attachment_id` | 图片/PDF/Word/Excel（P2 增视频） |
| 审核记录 | `review_id` | P0 两级审核；P1 三级审核轨迹 |
| 授权 | `consent_id` | 展示授权与撤回 |

### 9.3 文件规范

| 类型 | 层级 | 预览 |
|---|---|---|
| 图片 | P0 | 缩略图/原图 |
| PDF | P0 | PDF.js 在线预览 |
| Word | P0 | 展示文件名，可下载 |
| Excel | P0 | Excel 预览类库 |
| 视频 | P2 | 评估存储后启用，720P/1080P |

### 9.4 接口约定

- 统一 `HTTPS + /api/v1`、JSON、小写下划线字段命名。
- 统一响应 `{code, message, data, request_id}`；分页 `page/page_size`。
- 学号按字符串传递，保留前导零；导入接口幂等、含错误行报告。
- 接口细节自查优化，联调前冻结接口契约。
