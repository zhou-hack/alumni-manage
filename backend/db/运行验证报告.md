## 七、发现的问题与处置

| # | 严重度 | 问题 | 处置 |
|---|---|---|---|
| Q1 | 🔴 高 | **git 强更回退了 stats 学院排行 SQL**（`u.college_id`，v3 schema 已无此列），新编译后 /stats/colleges 必 500 | ✅ 已重新修复为 `archives ⋈ users ⋈ alumni_base` 关联（[JdbcStatsRepository.java](file:///c:/Users/huang/Desktop/alumni/backend/stats/src/main/java/com/alumni/stats/repository/impl/JdbcStatsRepository.java)），实测 200 |
| Q2 | 🔴 高 | **JDBC 时间读路径偏 +8h**：连接串只有 `serverTimezone=UTC` 时，服务器按会话时区(+08:00)转换后再被驱动按 UTC 解析，API 出参比真实 UTC 晚 8 小时（昨日"-8h 修数据"实为被该 bug 误导） | ✅ 两模块 AppConfig 默认 URL 改为 `connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true`，重启后出参 `13:43:33Z` 与存储 epoch 一致 |
| Q3 | 🟡 中 | AppConfig 默认库名为 `alumni`（不存在），无 env 直接启动会 500 | 未改源码默认值（尊重 git 强更决定）；**启动必须注入 `DB_URL` 环境变量**，已在 README 级记录（本报告 §八） |
| Q4 | 🔴 高 | **alumni_platform 库第四次无故消失**（本次验证前发现，已重建部署） | ⚠️ 环境问题待排查：检查 MySQL 数据目录持久化/是否有重置脚本或 Docker 卷策略 |
