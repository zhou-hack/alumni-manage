# 模块交付总览

> 校友管理平台后端 · 模块化单体（Modular Monolith）：**运行时单应用 / 单端口 / 单部署单元，代码按模块解耦**
> 基线：API 规范 v1.2 Final · 数据库 schema.sql v3（库 `alumni_platform`，MySQL 8.4）
> 更新：2026-09-20（drafts 草稿模块交付并入单体，冒烟 25 项）

---

## 〇、单体架构（当前形态，已实施）

**一个 Spring Boot 应用、一个 JVM、一个端口、一个部署单元：**

```
Internet → Nginx :443（HTTPS/域名/静态资源/基础限流，不做模块间路由）
         → alumni-platform.jar（Spring Boot :8080，全部 /api/v1/**）
```

- 唯一入口 `app/PlatformApplication`：扫描 `com.alumni` 全量装配，仅排除各模块独立调试用启动类；产物 `app/target/alumni-platform.jar`
- 模块间协作全部为 JVM 内部调用（共享库直写 + Spring bean 注入），**零跨模块 HTTP**
- 公共底座 `common`（`com.alumni.common`）：统一 `ApiResponse`/`ErrorCode`/`GlobalExceptionHandler`/`request_id` + **统一安全栈**（全平台唯一 `SecurityFilterChain` / `JwtAuthFilter` / `JwtService` 验签 / `AuthPrincipal` / `PasswordEncoder`）；auth 模块保留自己的 `JwtService` 负责 token 签发
- 组件名冲突：`ModuleBeanNameGenerator` 为跨模块同名 bean 生成带模块前缀的 bean 名
- JPA 实体重名：非归属模块的同名实体加 `@Entity(name = "模块前缀+类名")`，JPQL 同步
- 迁移合并：12 个模块迁移脚本合并为 `app/src/main/resources/db/platform/V1__platform_init.sql`（全量幂等，兼容「schema.sql 先行建库」与「Flyway 自建」两条路径），`spring.flyway.locations=classpath:db/platform`
- 冒烟验证：`app/smoke.ps1`（25 项：三种角色登录 + 各模块代表接口 + 401/403 越权断言 + drafts 乐观锁冲突断言）
- **模块仍可独立启动调试**：各模块 Application 以 `scanBasePackages = {模块包, com.alumni.common}` 复用公共安全栈，调试端口在模块各自 application.yml 中配置

## 二、甲线模块详情

### 2.1 auth（8080，`com.alumni.auth`）

用户认证与账号体系。

- 密码链路：前端 SHA-256 hex → 服务端 BCrypt 入库
- Token：access JWT（HS256，2h）；refresh 不透明随机串，MySQL 存 SHA-256 散列，7d 轮换；logout/重置密码后整户作废
- `users.uuid`：每账号绑定不可变 UUID v4（激活时生成），登录响应与 /me 均出参，供外部平台对接；内部关联仍用自增 id
- 发码限流：同手机号 60s 一次（429）；单 IP 每小时 ≤10 个 distinct 手机号（同号重发不占 IP 配额）
- 激活核验数据源：`alumni_base`；人工核验走 reviews 通道（`biz_type=activate_manual`，单级）

测试账号（均已激活，密码前端 SHA-256 后提交）：

### 2.2 dicts（8081，`com.alumni.dicts`）

基础字典，层级化。

- 落库类型：`college` / `major`（major 强制归属 college，`parent_id` 自引用）/ `honor_category`
- `grad_year` **虚拟类型不落库**：按当前年动态生成（默认 -20 ~ +4，可配 `app.dicts.grad-year-*-offset`）；该类型增删改一律 `409 INVALID_STATE`
- 写操作仅 school_admin；删除父级前有子项 `409 RESOURCE_REFERENCED`；被业务引用（alumni_base 文本对齐 / honors.category）禁删禁改值
- 设计原则：可枚举数据（年份）不做字典主数据；业务主数据才落库
- 迁移：V1 种子（37 条）→ V2 层级化（幂等 ALTER，见 §六）→ V3 grad_year 虚拟化

测试页：`http://localhost:8081/`

### 2.3 attachments（8082，`com.alumni.attachments`）＋ imports

**附件（规范第六章）**

- 统一上传 `POST /attachments`（multipart）：jpg/png/webp/pdf，单文件 ≤10MB，批量 ≤5（坏行不阻断好行）
- 图片压缩：最长边 ≤1280px → 质量递减 ≤2MB（需压质时转 JPEG；webp 输入归一为 PNG，TwelveMonkeys 解码）
- 内容嗅探：PDF 魔数 `%PDF-`、图片解码校验，伪装文件 `400 FILE_TYPE_NOT_ALLOWED`
- 预览权限继承：showcase 公开免认证 / unreferenced 仅本人+审核角色 / 未审核业务本人+审核角色 / approved 任意登录
- 删除仅审核角色；`ref_id` 非空 `409`；每次删除写 `attachment_audit_log`（保留 ≥180 天）
- 孤儿清理：`@Scheduled` 每小时清 unreferenced >24h；DB 写失败补偿删盘文件
- 存储：`./storage/{biz_type}/yyyy/MM/{uuid}.ext`

**imports 批量导入（规范第十一章，挂载本模块，URL 保持 `/api/v1/imports`）**

- 上传 csv/xls/xlsx（扩展名+魔数嗅探），≤10MB，≤2000 行；**csv 严格 UTF-8 解码**（GBK 直接 400）
- `@Async` 异步入 `alumni_base`：逐行校验（必填/身份证/手机/年份/批内学号去重），坏行记 `import_errors` 不阻断好行；**不开类级事务**（JdbcTemplate 逐行自动提交）
- 原表留存为 attachments 行（`biz_type=import`，`ref_id=任务id`）
- `GET /imports/template` 动态生成 xlsx（数据 sheet + 填写说明 sheet）
- 全链路仅 college_admin；任务仅上传本人可见

### 2.4 archives（8083，`com.alumni.archives`）

校友档案（规范第四章），业务主线核心。

- 状态机：`draft → pending_first → pending_second → approved`；驳回 `rejected`（可 resubmit，version+1）；任意状态 → `deleting` → `deleted`
- 7 接口：创建（submit 分流）/ my 列表 / 详情 / 管理端组合筛选（keyword 学号+姓名、college_id、grad_year、category、status、date 区间）/ 修改（仅 draft、rejected）/ 驳回重提 / 删除申请
- **跨模块直写契约**（共享库，不走 HTTP）：
  - 提交/重提/删除申请 → 直写 `reviews` + `review_logs`（create）
  - 附件绑定 → 直写 `attachments.ref_id/status/referenced_at`（四重校验：存在/本人/biz_type/未被他业务引用）
- **懒同步** `syncReviewOutcome`（读取时自愈 reviews 只写 status 的缺口）：
  - rejected → 补驳回原因回显
  - deleting + 删除审核被驳回 → 恢复 `prev_status`（扩展列，V1 迁移幂等补列）并回显原因
  - deleted → 释放关联附件为 unreferenced
- 管理端筛选：keyword 经 `users ⋈ alumni_base`；college_id 经 dicts.label 文本对齐

测试页：`http://localhost:8083/`

## 三、乙线模块（kaijie）

| 模块 | 说明 |
|---|---|
| reviews（规范第七章） | Review 独立资源，双级审核（学院 first / 校级 second），`activate_manual` 单级；审核后**直写** `archives.status` / `honors.status`；`archive_delete` 终审通过置 `deleted`，驳回不动业务（archives 懒恢复兜底）；日志本人+审核角色可见 |
| stats（规范第十章） | 不建表纯聚合：overview / honors 分布 / colleges 排行（`archives ⋈ users ⋈ alumni_base.college` 文本 JOIN）；已对齐 v3 库 |
| consents（规范第九章） | `(archive_id, scope)` 唯一；撤回=删行并联动 showcase 下架；上架前置条件之一 |
| honors（规范第五章） | 🔨 骨架：独立结构化资源（level/awarded_at 统计字段），可 `archive_id` 关联档案；统计口径唯一来源 |
| showcase/screen（规范第八章） | 🔨 骨架：上架条件 approved+有效 consent；screen 免认证，未授权资料绝不出现（红线） |
| drafts（规范第十二章） | localStorage 为主、服务端兜底；(user_id, biz_type) 唯一一行；版本号乐观锁（冲突 409 DRAFT_VERSION_CONFLICT，data 携带服务端最新草稿）；提交版本 > 服务端版本时采纳客户端（防服务端清理后卡死）；archives 正式提交成功后直写删行 |

## 四、跨模块契约（共享库直写约定）

```
auth ──签发 JWT──> common 统一验签（全平台唯一 JwtAuthFilter，同一 JWT_SECRET）
archives ──直写──> reviews / review_logs（biz_type=archive / archive_delete）
reviews  ──直写──> archives.status / honors.status（审核结果）
业务方  ──直写──> attachments.ref_id + status=referenced + referenced_at
consents ──撤回──> showcase 行删除（联动下架）
imports ──直写──> alumni_base（好行）/ import_errors（坏行）
archives ──正式提交──> drafts 行删除（submit=true 后服务端草稿自动清理，API 规范 12.1）
```

- 附件是否被引用：看 `attachments.ref_id IS NOT NULL`（不做跨表 JOIN）
- reviews 与业务表状态一致性：reviews 只写 status，**驳回原因与删除恢复由 archives 读取时懒同步**
- showcase 行存在 = 上架中 + 封面快照

## 五、单体合并记录（已完成）

原端口冲突问题已随单体合并消解：**运行时只有一个应用（:8080）**，模块不再各自占用端口。合并时处理的问题与方案：

| 问题 | 方案 |
|---|---|
| 10 套同构安全栈（AuthPrincipal/JwtService/JwtAuthFilter/SecurityConfig 复制） | 收敛进 `common`（35 个重复文件删除，仅保留 auth 的签发 JwtService）；模块业务代码统一 import `com.alumni.common.security.AuthPrincipal` |
| `@AuthenticationPrincipal` 类型不匹配（common 过滤器写入的 principal 与模块各自类型不符 → 注入 null → 500） | 统一 principal 类型后根治 |
| JPA 实体同名冲突（多个模块各有一份 Archive/User 等实体映射） | 非归属模块实体加 `@Entity(name = "模块前缀+类名")`，JPQL 同步 |
| Flyway 版本号冲突（多模块同版本 V1/V2） | 合并为 app 专属目录 `db/platform` 单脚本，全量幂等 |
| 跨模块同名 bean | `ModuleBeanNameGenerator` 前缀命名 |
| 原端口冲突（reviews/attachments 8082、stats/dicts 8081、showcase/archives 8083） | 单体下不复存在；模块独立调试时的调试端口互不影响 |

## 六、数据库与迁移约定

- **唯一基准**：`backend/db/schema.sql` + `backend/db/数据库设计方案.md`（15 表 19 外键 + archives.prev_status 扩展列）
- 单体 Flyway：`app` 模块 `db/platform` 目录（V1 全量幂等合并脚本 + V2 drafts 幂等补建，`baseline-on-migrate`，兼容 schema.sql 先行建库与非空库基线跳过）；模块独立调试时仍用各自 `db/migration`
- 迁移脚本 `CREATE TABLE IF NOT EXISTS` 起手；**ALTER 必须幂等**（information_schema 判定 + 存储过程包装），兼容"schema.sql 先行建库"与"Flyway 自建"两条部署路径（dicts V2 / archives V1 已按此执行）
- MySQL JDBC URL：`characterEncoding=UTF-8`（Java 字符集名，写 utf8mb4 连不上）
- 业务时间字段 ISO 8601 UTC；实体用 `@CreationTimestamp`/`@UpdateTimestamp` 保证 Java 侧即时有值
